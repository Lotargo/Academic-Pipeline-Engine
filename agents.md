# Методология AIOps Pipeline

Этот документ регламентирует работу автоматизированных агентов внутри системы Academic Pipeline Engine.

## 1. Роли и Ответственность

### Orchestrator (Finite State Machine)
*   **Задача:** Управление жизненным циклом документа через FSM с guards.
*   **Правило:** Переходы `INIT → DRAFTING → REVIEWING → RENDERING → DONE` с проверкой через `transition_to()`. Состояние `FAILED` при ошибках.
*   **Запрет:** Нельзя пропускать этап Review (REJECT → возврат в DRAFTING, до 3 попыток).

### Writer (Writer Agent)
*   **Задача:** Генерация контента по запросу Оркестратора.
*   **Формат:** Markdown с LaTeX-формулами (`$E=mc^2$`).
*   **Стиль:** Академический, безличный.

### Reviewer (Reviewer Agent)
*   **Задача:** Валидация сгенерированного текста.
*   **Формат ответа:** Ровно одна строка: `APPROVED` или `REJECTED: <причина>`.
*   **Критерии:**
    *   Отсутствие галлюцинаций в цифрах.
    *   Соответствие тона (Tone of Voice).
    *   Отсутствие маркеров AI (клише «в заключение хотелось бы сказать»).

## 2. Технические стандарты

*   **Конфигурация:** Все промпты (`system_prompt`, `pipeline.sections`) и параметры моделей (`model`, `temperature`) хранятся в `config/agents.yaml`. Хардкод в Python запрещен.
*   **Инструменты:** Верстка (Docx Renderer) отделена от генерации текста. Агент не генерирует бинарники, он генерирует структуру данных.
*   **Абстракция LLM:** Код использует `LLMProvider` (ABC). Реальные вызовы — через `OpenAIProvider`, тесты — через `MockProvider`.
